# CareerLens

面向学生求职的开源简历诊断与岗位匹配系统。基于 Resume Matcher 固定版本构建，使用 Next.js、FastAPI 和 SQLite。同一份代码支持本地个人使用和网站多人使用，采用 [Apache-2.0](LICENSE) 许可。

在线使用：**[careerlens.cc](https://careerlens.cc/)**。邮箱验证注册后一次性赠送 20 积分，使用运营者提供的 DeepSeek 服务；每次成功模型生成扣 1 积分。部署配置与线上验收见 [Azure 部署记录](docs/Azure部署记录.md)。

## 实时岗位与 JD 记忆

进入“实时岗位”，默认查询国家大学生就业服务平台的国内多雇主岗位，主要覆盖高校毕业生、校招和实习。每次读取 10 条并获取完整 JD，查询页缓存 5 分钟。页面显示雇主、地区、人民币月薪、发布日期、更新时间和获取时间；公开检索计数单独标记，空页停止后翻。图表和解读仅使用本页完整样本。

可切换 Jobicy 查询多公司国际远程机会，同一关键词和地区缓存一小时、最多 200 条样本；China 筛选包含跨地区远程机会，具体以 JD 的地区限制为准。腾讯来源只覆盖腾讯自身岗位。BOSS 匿名接口本次返回环境检测错误，尚未接入；各国内平台的实际响应与接入范围见[国内招聘来源接入记录](docs/国内招聘来源接入记录.md)。

点击“使用并记住这份 JD”后，可在“目标岗位”校对并继续诊断。也可以直接粘贴其他平台的 JD，点击“记住这份 JD”，下次从折叠的“最近使用的 JD”回填。公司、来源、要求校对、历史记录及统计图表均按需展开。

JD 从版本 1 开始，编辑提交携带 `expected_version`；其他页面先保存时返回 409，保留本次编辑并提供最新内容供合并。方向推荐与市场解读分别保存输入快照、结果和时间，支持查看、导出与删除历史；原简历或岗位删除后，已保存的方向和统计快照仍可查看。

浏览和统计岗位不写入本地岗位表，只有主动记住的 JD 才保存。原有个人记录保留，虚构岗位从主工作台隐藏；示例生成脚本仅供测试使用。API 不需要额外密钥，上游不可用时明确提示。主工作台采用桌面编辑器布局：左侧切换功能与简历文档，顶部工具栏提供保存、预览、导入和导出，正文连续编辑。紫色与原创小图标保留品牌识别；简历长文本随内容增高，章节目录用于直接跳转。接入范围和接口见 [实时岗位接入说明](docs/实时岗位与JD记忆.md)，生成图标及插图见 [插画资产说明](docs/CareerLens-插画资产.md)。

## 本机运行

访问 **http://127.0.0.1:3000**。接口文档在 **http://127.0.0.1:8000/docs**。

本轮构建已在 macOS Apple Silicon 上运行，实际环境为 Python 3.13.15、Node.js 24.19.0、npm 11.6.2、uv 0.12.10。依赖由 `app/apps/backend/uv.lock` 和 `app/apps/frontend/package-lock.json` 固定。

重新安装或在新机器启动，需要先准备 Python 3.13、Node.js 22 或 24、npm 和 uv。Node.js 22 是上游 Docker 基础版本，本机验证使用 24。安装依赖前先停止正在运行的开发服务。

```bash
cd /path/to/careerlens
bash scripts/setup.sh
bash scripts/dev.sh
```

`setup.sh` 安装前后端依赖及 PDF 导出所需的 Chromium，初始化空数据库，并下载校验本地语义模型。模型暂时下载失败时仍可使用基础功能。首次安装需要网络；前端构建会下载 Google Fonts。Linux 导出中文时需安装 Noto CJK 字体和 Playwright 的系统依赖。`dev.sh` 将服务绑定到本机，按 Ctrl+C 停止。

启动日志保存在 `.local/logs/backend.log` 和 `.local/logs/frontend.log`，可在另一个终端运行 `tail -f .local/logs/backend.log .local/logs/frontend.log` 查看。首次启动等后端日志出现 `Application startup complete`、前端日志出现 `Ready` 后打开页面。端口固定为 8000 和 3000；启动失败时先查看日志及端口占用。

本次机器缺少全局 Node.js、npm 和 uv，已使用本机现有运行环境，并在忽略目录 `.local/runtime.env` 中配置了启动脚本所需路径。该文件不进入 Git，新机器按常规方式安装以上工具即可。

也可以在两个终端分别启动：

```bash
# 终端一
cd app/apps/backend
uv run --frozen python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

```bash
# 终端二，从工程根目录开始
cd app/apps/frontend
npm run dev -- --hostname 127.0.0.1
```

## 模型配置

AI 辅助默认开启。本地模式可从侧栏进入“模型设置”，选择提供商，填写模型标识、API Key；自定义兼容接口填写 Base URL。点击“保存设置”和“测试连接”后即可使用。网站模式由运营者统一配置模型。首页开关可以手动关闭 AI。复用上游的加密密钥存储，凭据不会出现在诊断 JSON 中。

关闭 AI 后，规则匹配、编辑、事实整理、版本管理、统计和 PDF 导出正常工作，顶部显示“AI 已关闭”。启用远程模型后，所选材料会发送给配置的服务。

AI 诊断、岗位方向推荐和单段润色提供求职建议，引用用于定位材料，不证明经历真实性。当前保留输出结构与来源标识检查，已取消额外事实核验及角色、数字、技能等生成门槛；采纳仍创建独立简历版本并保留原稿。

正常情况下，单岗位诊断、一次方向推荐、一次单段润色各生成 1 次；多岗位比较逐岗生成，市场解读可能生成 2 次。旧完整简历优化仍包含多个生成步骤，按实际成功生成次数计费。保存失败或取消时释放本次操作的预留积分，已提交的结果与账务保持有效。

文件导入遵循侧栏的 AI 开关；AI 服务失败时保留文件原文，返回规则草稿及提示。保存时同时更新原文和结构化字段；编辑冲突检查包含原文和版本名称，历史诊断仍保留冻结的结构化材料。

## 多岗位比较与语义检索

进入“诊断与优化”，选择已保存的简历，在“多岗位横向比较”，勾选 2—5 个岗位并比较。各岗位共享同一份简历快照，显示材料覆盖度、待确认项和条件状态；可以打开单岗证据或导出比较 JSON。确认学历、经验、到岗情况会生成新的诊断记录，旧记录保持不变。

“语义检索相关经历”使用本机 [multilingual-e5-small 的 ONNX 版本](https://huggingface.co/Xenova/multilingual-e5-small)，从工作和项目经历中提供少量候选。检索相似度不参与评分，核对后由既有规则计算分数；检索失败时保留关键词结果。模型文件固定版本并校验 SHA-256，约 135 MB，保存在忽略目录 `app/apps/backend/data/models/`。推理无需联网或额外 API Key。

如需重新准备模型，在后端目录执行：

```bash
uv run --frozen python -m app.scripts.prepare_embeddings
```

## 首次体验

1. 在“我的简历”点击“导入”，选择文件或粘贴原文；也可以新建空白简历直接编辑。完成后点击“保存简历”，或使用 ⌘S / Ctrl+S。
2. 在“实时岗位”搜索目标方向，展开 JD 后点击“使用并记住这份 JD”；或在“目标岗位”直接粘贴 JD 并记住。
3. 校对岗位要求，进入“诊断与优化”，选择简历和 JD，点击“分析目标 JD 匹配度”。
4. 选择一段经历，填写本人可以确认的事实，审阅来源。采纳后生成独立定向版，可比较同一 JD 下的覆盖度并导出 PDF。
5. 在“实时岗位 → 已保存岗位分析”选择类别、城市与时间，点击“更新岗位统计”，再解读当前样本；也可在实时招聘搜索中查看本页岗位统计。

继续优化第二个段落时，选择刚生成的定向版重新诊断，再生成下一条建议。同一基础版上的多条建议各自生成独立版本。

## 数据与初始化

数据库自动创建在 `app/apps/backend/data/resume_matcher.db`。SQLite 数据库、原始个人材料、密钥、缓存和 `.env` 均被 Git 忽略。请将整个后端 `data/` 目录作为本机数据备份；备份时停止服务，使数据库和密钥文件保持一致。

```bash
cd app/apps/backend
# 幂等初始化；去掉 --demo 即为空库初始化
uv run --frozen python -m app.scripts.career_data init --demo
# 导入 JSON 岗位数组，逐条校验来源与要求引用
uv run --frozen python -m app.scripts.career_data import-jobs /absolute/path/jobs.json
# 从实际 ORM 重新生成建表 SQL
uv run --frozen python -m app.scripts.career_data schema /absolute/path/schema.sql
```

格式见 [示例数据说明](data/README.md)。岗位删除会清理对应诊断与建议；简历删除会清理对应快照、诊断、建议和修改记录。其他独立简历版本保留，删除前页面会说明范围。整个工作区重置入口沿用设置页。

本地模式保留原个人工作区；网站模式使用独立的账号数据库与每用户数据库。网站部署的默认数据卷与本地卷分开，原本地记录不会自动分配给网站注册用户。详见 [网站部署指南](docs/网站部署指南.md)。

认证库 `auth.sqlite` 与业务库分别使用编号、校验和及逐版本事务迁移。旧余额完整保留，以“期初余额”记录，不补造历史消费。网站保存 AI 结果时，通过 SQLite ATTACH 同时提交业务结果和积分结算；失败或取消释放本次预留，启动及每 60 秒恢复过期预留。账户页可查看可用/预留积分、逐次流水与充值订单。迁移要求、微信 Native 配置和升级回退流程见 [规则调整与账务升级](docs/规则调整与账务升级_2026-09-10.md)。

## Docker

根目录提供本项目的源码构建配置，不拉取上游应用成品镜像：

```bash
docker compose up --build -d
```

本地数据持久化在 `careerlens-data` 卷，访问本机 3000 端口。网站版使用独立配置：

```bash
cp .env.hosted.example .env.hosted
# 填写域名、随机认证密钥和 SMTP 配置后启动
docker compose --env-file .env.hosted -f compose.hosted.yaml up --build -d
```

网站只由 Caddy 公开 80/443 端口，自动申请 HTTPS 证书。详细配置、更新与备份操作见 [网站部署指南](docs/网站部署指南.md)。本次环境没有可用的 Docker Compose／守护进程；容器镜像构建与真实域名证书申请需在目标服务器执行。
