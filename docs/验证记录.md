## 关键行为验证

新增检查覆盖 C++、C#、R、A/B Testing、Java 与 JavaScript 区分、否定与学习计划、重复要求、空要求、学历未知、重叠月份、薪资缺失、重复 JD、合成数据排除，以及以下事务行为：

- 重复采纳返回同一简历 ID，数据库只创建一个结果。
- 修改源简历或 JD 后，旧草稿采纳返回 409。
- 人工修正证据关系生成新诊断，旧记录保留原判断。
- 拒绝的草稿不能再次采纳。
- 删除简历后，关联诊断不能继续读取。
- 模型返回无来源的数字或工具时，建议被拒绝，原始材料保持不变。
- 市场模型返回不存在的筛选值时请求失败，原统计仍可读取。

上述模型测试使用可控替身，验证协议和失败行为，没有用它们代替真实模型质量评估。

## 本轮发现并处理的问题

| 问题 | 处理与复核 |
| --- | --- |
| 上游无跟踪的 Python 锁文件 | 生成并提交 `uv.lock`，后端及 Docker 改用冻结安装 |
| 规则解析把短项目名称误识别为章节标题 | 限制为完整标题模式，示例项目及经历证据保留正确 |
| JD 中“本科，硕士优先”被当成硕士门槛 | 优先项不进入普通学历门槛，增加边界测试 |
| 技能热力图部分低频技能被提前截掉 | 后端保留各类别完整计数，前端只选择展示列 |
| 图表手机页面溢出 | 网格列改为可收缩的 `minmax(0,1fr)`，重新检查实际宽度 |
| 格式化触及上游说明文件 | 撤回无关格式变化，只提交本轮必要改动 |
| 前端清洁安装发现可选依赖锁条目不完整 | 在不含 `node_modules` 的临时目录修复锁文件，再执行 `npm ci` 和启动脚本验证 |
| 上一终端断开后，残留服务仍监听端口，但 PDF 导出返回 500 | 确认残留进程的标准输出和错误输出已被撤销；受控重启并将服务日志改为文件输出后，一页和两页 PDF 均导出成功。启动脚本增加 SIGHUP 清理，并固定前后端地址和端口 |
| 简历选择器重复显示“定向版” | 统一版本标签显示；同时修正项目经历数量文案。TypeScript 与 ESLint 复验通过 |
