# AI 诊断失败排查与修复

## 结论与证据范围

2026-09-09 用户截图中的提示来自岗位匹配接口的后端异常处理。线上日志在北京时间 22:50:58 和 22:51:09 连续记录模型结果校验的 `ValueError`，随后 `/api/v1/career/matches` 返回 502。旧日志只保存异常类型，无法还原该用户触发的具体字段，也不能据此断言其当时是否扣除了积分。

使用相同的 DeepSeek 模型和完全合成的简历、岗位材料，在独立临时数据库中复现了同类错误。排查未读取用户简历、验证码、会话令牌或模型密钥。失败过程的数据库回归确认：原简历、岗位、已有匹配保持不变，不保存半成品分析。

## 已修复的问题

1. **角色检查误判。** 旧代码只要看到“独立完成”“主导”等词，而简历没有同词，就拒绝结果。因此，“当前材料未提供独立完成调研的证据”、核实问题、未来实践任务及引用岗位要求，都可能误报。现在仅对明确的既有角色升级作确定性拦截，其余表述仍必须通过独立事实复核。
2. **表达建议误判。** 旧代码按“量化”“补充”等裸关键词拦截表达建议，连保留已有数字或“不补充未知信息”也可能失败。已移除此规则，保留数字、技能、角色、用途的来源检查及独立事实复核。
3. **自动修正信息不足。** 模型可能把不相邻的 JD 片段拼成一条引文。现在仍严格要求连续原文引用，同时反馈错误字段、错误引用和上一版结果，并汇总同一版的全部独立校验问题，避免一轮只修一处、下一轮才发现另一处。未知角色或成果的表达建议会收到明确的修正要求。
4. **不完整 JSON 缺少重试。** 解析失败现在允许一次受总时限约束的重试，并增加该次输出上限。每个生成阶段最多两次尝试，仍受 60 秒总时限约束。
5. **报错原因混在一起。** 接口现在区分结构错误、引用错误、不受原文支持的结论、复核错误、超时及材料过长。日志记录操作和固定错误代码，不记录私人材料或供应商响应正文。
6. **整次诊断失败仍可能扣分。** 原逻辑仅退还失败的单次生成；已经成功的初稿或审查可能计费，即使最终没有结果。现在岗位匹配、批量比较和方向推荐在异常或取消时，等待子任务完成退款，再退还本次操作此前的成功扣费。成功操作仍按每次生成扣 1 积分，并发操作分别结算。

历史失败是否实际扣费无法由旧日志精确确定，本次没有猜测并修改历史余额。进程硬崩溃后的自动对账仍需要持久化积分流水，这项运行限制没有在本次改动中解决。
