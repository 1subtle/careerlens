## 4. 配置文件与读取位置

| 位置 | 用途 | 共享方式 |
| --- | --- | --- |
| 后端工作目录 `.env` | 由 Settings 和 HostingSettings 读取；部署进程环境变量可传入同名配置 | 真实值不入库，只共享示例与变量说明 |
| `data/config.json` 与加密密钥存储 | 本地模型设置、非敏感选项及独立加密凭据；`data/` 随私人备份保留 | 不纳入源码包 |
| 根目录 `.env.hosted.example` | 网站域名、认证、SMTP、AI 配置示例 | 随源码共享 |
| 根目录 `.env.hosted` | Compose `--env-file` 读取；不是所有源码启动命令都会自动读取它 | 运营者在部署服务器创建 |
| `.local/runtime.env` | 启动脚本可选读取的当前机器工具路径 | 忽略，不作为通用安装前提 |
| 前端环境变量 | Next.js 构建和启动时读取；`NEXT_PUBLIC_*` 可能进入浏览器代码 | 只放可公开值，不能放密钥 |

## 5. 主要环境变量

| 变量 | 默认或允许值 | 作用与配置要求 |
| --- | --- | --- |
| `CAREERLENS_MODE` | `local` / `hosted`；默认 `local` | 是否启用邮箱身份和每用户工作区 |
| `DATA_DIR` | 后端 `data/` | 数据、配置和缓存根目录；测试用独立路径 |
| `FRONTEND_BASE_URL` | 配置类默认 localhost:3000；脚本固定 `http://127.0.0.1:3000` | 后端 Chromium 访问内部打印页 |
| `BACKEND_ORIGIN` | `http://127.0.0.1:8000` | Next.js API 代理目标 |
| `NEXT_PUBLIC_API_URL` | Docker 构建默认 `/` | 浏览器同源 API 前缀，不含凭据 |
| `LLM_PROVIDER` | openai、openai_compatible、azure_foundry、anthropic、openrouter、gemini、deepseek、groq、ollama | 提供商适配；本地也可在设置页配置 |
| `LLM_MODEL` | 配置类默认 `gpt-5-nano-2025-08-07`；hosted 示例为 `deepseek-chat` | 使用实际服务支持的模型标识；历史验证另有模型标识，不与默认值混同 |
| `LLM_API_BASE` | 可空 | 自定义或兼容 API 地址；DeepSeek 示例为 `https://api.deepseek.com` |
| `LLM_API_KEY` | 默认空 | 仅服务端持有；网站由运营者统一配置 |
| `REQUEST_TIMEOUT_SECONDS` | 默认 240，限制 30—1800 秒 | 后端通用 AI 总时限，不能只修改这一层 |
| `NEXT_PUBLIC_REQUEST_TIMEOUT_MS` | 默认 240000，限制 30000—1800000 毫秒 | Next.js 代理与客户端总时限；与后端保持一致；具体业务可有更短时限 |
| `PREVIEW_TTL_SECONDS` | 默认 86400，限制 60—604800 秒 | 临时预览有效期 |
| `LOG_LEVEL` / `LOG_LLM` | 默认 INFO / WARNING | 允许 CRITICAL、ERROR、WARNING、INFO、DEBUG；提交日志前脱敏 |
| `CAREERLENS_DOMAIN` | 示例 `career.example.com` | Compose/Caddy 域名，不含协议与路径；不会自动创建 DNS |
| `CAREERLENS_PUBLIC_URL` | hosted 必填；Compose 从域名生成 HTTPS URL | 校验请求来源与安全 Cookie；仅本机允许 HTTP |
| `CAREERLENS_AUTH_SECRET` | hosted 至少 32 字符随机串 | 会话与验证码安全；不得使用文档中的固定示例值 |
| `CAREERLENS_SMTP_HOST` / `PORT` | 默认端口 587；1—65535 | 邮件服务，需实际验证发信 |
| `CAREERLENS_SMTP_USERNAME` / `PASSWORD` | 同时提供或同时为空 | 用户名与密码/授权码配对配置 |
| `CAREERLENS_SMTP_FROM` | 必须和 HOST 配套 | 已验证发件身份；不得包含换行 |
| `CAREERLENS_SMTP_SECURITY` | `starttls`、`ssl`、`plain` | 默认 starttls；plain 仅本机测试收件箱 |
| `CAREERLENS_GITHUB_URL` | 可空，GitHub HTTPS 地址 | 网站开源链接，不自动创建远程仓库 |

## 6. 模型、数据库与容器资产

语义检索使用 `Xenova/multilingual-e5-small` ONNX，固定 revision 为 `761b726dd34fb83930e26aab4e9ac3899aa1fa78`。准备脚本下载并校验 SHA-256，CPU 本地推理，最多给每项要求提供 3 条候选；相似度不直接计入规则覆盖度。

数据库初始化必须运行应用：`uv run --frozen python -m app.scripts.career_data init`。如需核对业务 DDL，可在后端目录执行以下命令生成新文件，先检查差异再替换旧文档或交付 SQL：

```bash
uv run --frozen python -m app.scripts.career_data schema /tmp/careerlens-current-schema.sql
```

该命令生成业务 ORM 的 SQL，不包含独立 `auth.sqlite` 的认证建表脚本。认证数据库由 hosted 启动逻辑初始化；合并设计文档分别说明业务库和认证积分库。旧 `data/schema.sql` 的字段和认证表缺口见[缺陷与修复记录](缺陷与修复记录.md)。

本地 Compose 只绑定 `127.0.0.1:3000`，使用 `careerlens-data` 卷；网站 Compose 使用独立 `hosted-data`，由 Caddy 公开 80/443，应用端口不直接公开。`app/Dockerfile` 中 Chromium、系统库和 CJK 字体安装属于容器运行条件。基础镜像标签没有固定内容 digest，因此本轮不把它描述为字节级可复现镜像。

## 7. 配置核验与交付

安装用 `uv sync --frozen` 和 `npm ci`，不手工猜测传递依赖。修改配置后重启对应服务；更改 `NEXT_PUBLIC_*` 时重新构建生产前端。本地使用、网站使用、备份恢复和故障定位的具体顺序见系统运行说明与网站部署指南。

交付保留源码、锁文件、配置示例、初始化脚本和本说明；排除 `.env`、个人数据库、加密密钥文件、上传/导出材料、`.local/` 和备份。尚未同步的旧依赖清单与 DDL 已登记，不能据此写成“所有配置文件及数据库脚本均完成最终一致性验收”。
