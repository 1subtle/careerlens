# CareerLens 测试计划与测试用例

编制日期：2026-09-09。对应指导书第 18 页第 4.3、5.2 项及第 21 页功能验证要求。本计划用于现有实现的持续测试和最终验收；执行结果统一记录在[测试报告](测试报告.md)，缺陷进入[缺陷与修复记录](缺陷与修复记录.md)。

## 1. 范围与通过条件

测试覆盖“简历导入与保存 → JD 校对 → 证据诊断 → 事实核对 → 草稿审阅 → 独立版本 → 复评与导出”，并覆盖实时岗位、市场统计、网站登录和账号隔离。需求编号沿用[需求分析](需求分析.md)；网站身份与隔离对应 FR-15，照片和独立版式对应 FR-16。

功能验收以输入、可见行为、持久化结果和异常恢复为依据。核心链路必须能够完成，原稿与历史记录不能被误覆盖，跨账号访问必须被拒绝，未经核实的草稿不能绕过确认直接采纳。自动化测试通过与真实模型质量、跨环境部署分别验收。

| 层次 | 方法与工具 | 检查重点 | 证据形式 |
| --- | --- | --- | --- |
| 规则单元 | pytest，公开合成材料 | 关键词边界、要求权重、否定、薪资单位、事实约束 | 用例名称、断言、执行日志 |
| 后端接口集成 | pytest + httpx ASGITransport + 临时 SQLite | 真实路由、事务、冲突、删除、权限 | HTTP 状态、返回字段、数据库结果 |
| 前端组件 | Vitest + Testing Library + jsdom | 用户操作、状态反馈、草稿恢复、账号切换 | 组件断言、JSON 结果 |
| 完整浏览器链路 | 实际服务和浏览器 | 页面联调、下载、字体、分页与响应式 | 脱敏截图、导出检查记录 |
| AI 质量 | 固定材料、真实模型、人工复核 | 引文忠实性、无依据扩写、定向表达 | 模型与时间、原始输出、复核表 |
| 部署恢复 | 干净源码环境、Docker 与备份副本 | 锁定安装、启动、重启、恢复、HTTPS | 环境版本、命令、日志、验收记录 |

## 2. 数据与隔离

默认自动化使用仓库公开的 `data/examples/`、后端测试 fixture 和测试内声明的合成材料。`tests/conftest.py` 在导入应用之前设置临时 `DATA_DIR`，逐用例替换数据库与配置，并阻止意外外网连接。SMTP、招聘来源和模型调用使用可控替身；前端组件测试模拟 API。

课堂演示可使用[原始与优化简历对照](原始与优化简历对照.md)的完整示例。真实质量验收另用经同意、脱敏、编号后的材料；合成材料不能计入课程要求的 3 位学生简历与 5 份真实 JD。真实样本的采集和授权状态见调研及数据文档。

测试记录使用 TC 编号；一个 TC 可以对应多个参数化自动化用例，TC 数量不与 pytest/Vitest 数量直接相加。

## 5. 执行与记录方式

依赖安装完成后，在后端目录使用 `uv run --frozen --extra dev pytest`；默认排除真实模型 eval。前端目录依次执行 `npm run lint`、`npm run typecheck`、`npm test`、`npm run build`。专项复现命令与本轮逐文件数量见测试报告。

服务启动后可在项目根目录执行 `python3 scripts/smoke.py --artifacts .local/qa` 验证 HTTP 与 PDF 闭环。脚本会建立并清理自身的合成记录，因此应在专门的测试工作区执行。真实网站模式必须通过浏览器身份流程验证，不能把本地 smoke 脚本当作网站认证测试。

缺陷记录至少填写触发步骤、实际与预期结果、影响范围、修复文件、回归用例和复核时间。阻断性问题修复后先重跑对应专项，再完成最终回归。2026-09-10 至 09-12 的执行结果由实际测试补入，当前文档不预记完成。
