# CareerLens 运行指南

本文说明如何从源码包或 GitHub 仓库安装、启动和验证 CareerLens。本地个人使用选择 `local` 模式；公开网站选择 `hosted` 模式，配置见[网站部署指南](网站部署指南.md)。

## 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | macOS、Linux；Windows 使用 WSL2 或 Docker Desktop |
| 源码运行 | Python 3.13、Node.js 22、npm、uv 0.12.10、Bash |
| 容器运行 | Docker Engine / Docker Desktop，Docker Compose v2 |
| 数据库 | SQLite，应用自动初始化，无需单独安装数据库服务 |
| 资源 | 建议预留 4 GB 内存和 10 GB 磁盘供依赖、浏览器和构建使用 |
| 网络 | 首次安装需下载依赖、Chromium、字体和语义模型；AI 与岗位搜索需访问对应服务 |

Node.js 24 也已用于本地开发验证；交付构建使用 Node.js 22。依赖版本以[锁文件和版本表](配置与依赖说明.md)为准。

## 安装前准备与获取源码

以下步骤分别给出执行位置、命令和成功标志。Docker 与本地源码运行二选一；第一次安装建议按顺序完成各步骤，再使用一键脚本。

### 步骤 1：准备终端与基础工具

macOS 使用“终端”；Linux 使用 Bash 终端。Windows 使用 WSL2 Ubuntu：在**管理员 PowerShell** 中执行以下命令，按提示重启电脑，再启动 Ubuntu 并设置 Linux 用户名和密码。

```powershell
wsl --install -d Ubuntu
wsl --list --verbose
```

**检查结果：** Ubuntu 对应的 `VERSION` 为 `2`。后续标记为 `bash` 的命令均在 Ubuntu 终端执行。详细操作见 [Microsoft WSL 安装说明](https://learn.microsoft.com/en-us/windows/wsl/install)。

Ubuntu / WSL2 Ubuntu 安装基础工具：

```bash
sudo apt-get update
sudo apt-get install -y git curl ca-certificates unzip nano
```

macOS 如尚未安装 Git，执行以下命令，在弹出的窗口中完成 Command Line Tools 安装：

```bash
xcode-select --install
```

已有工具时直接检查：

```bash
git --version
curl --version
```

**检查结果：** 两条命令显示版本号。源码 ZIP 也可通过系统解压工具打开，Git 主要用于克隆和更新仓库。

### 步骤 2：取得源码并确认项目根目录

从 GitHub 获取，需使用有仓库访问权限的账号：

```bash
mkdir -p "$HOME/projects"
cd "$HOME/projects"
git clone https://github.com/1subtle/careerlens.git
cd careerlens
```

使用交付 ZIP 时，先在文件管理器中解压，再在终端进入解压后的 `CareerLens/`。命令行示例：将第一行路径替换为收到的实际 ZIP 路径。

```bash
career_archive="$HOME/Downloads/CareerLens-source-提交短号.zip"
mkdir -p "$HOME/projects/careerlens-delivery"
unzip "$career_archive" -d "$HOME/projects/careerlens-delivery"
cd "$HOME/projects/careerlens-delivery/CareerLens"
```

使用新的解压目录，避免与旧版本文件混放。WSL2 将项目放在 Linux 用户目录下，例如 `~/projects/`；从 Windows 下载的文件可通过 `/mnt/c/Users/你的Windows用户名/Downloads/` 访问。

确认目录，并记录后续命令使用的根路径：

```bash
export CAREERLENS_ROOT="$(pwd)"
ls README.md compose.yaml scripts/setup.sh \
  app/apps/backend/pyproject.toml app/apps/frontend/package.json
```

**检查结果：** 上述文件均存在。后续示例使用 `CAREERLENS_ROOT`；新开终端后应先进入项目根目录，再执行 `export CAREERLENS_ROOT="$(pwd)"`。

ZIP 内的 `SOURCE-MANIFEST.json` 记录提交版本和各文件 SHA-256，包外 `.sha256` 用于检查压缩包完整性，方法见[验证说明](验证说明.md#源码包生成与复核)。

## 方法一 Docker 安装与运行

此方法由镜像构建完成 Python、Node.js、依赖、中文字体、Chromium 和语义模型安装，数据库在首次启动时自动初始化。宿主机无需再安装本地源码运行环境。

### 步骤 1：安装并启动 Docker

macOS 按 [Docker Desktop for Mac](https://docs.docker.com/desktop/setup/install/mac-install/) 下载对应芯片版本，安装后启动 Docker Desktop。Windows 按 [Docker Desktop for Windows](https://docs.docker.com/desktop/setup/install/windows-install/) 安装，启用 WSL2 后端及 Ubuntu 的 WSL Integration，然后在 Ubuntu 终端执行后续命令。

Ubuntu 服务器可按 [Docker Engine 官方安装说明](https://docs.docker.com/engine/install/ubuntu/) 安装。以下命令适用于尚未安装 Docker 的 Ubuntu，按顺序配置软件源并安装 Engine、Buildx 和 Compose：

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
  -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
. /etc/os-release
sudo tee /etc/apt/sources.list.d/docker.sources > /dev/null <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: ${UBUNTU_CODENAME:-$VERSION_CODENAME}
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io \
  docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
```

检查客户端、Compose 和 Docker 服务：

```bash
docker --version
docker compose version
docker info
```

**检查结果：** Compose 为 v2 或更新兼容版本，`docker info` 能显示服务端信息。Ubuntu 普通账号若无 Docker socket 权限，下文的 `docker` 命令统一使用 `sudo docker` 执行；Docker Desktop 一般不需要 `sudo`。

### 步骤 2：检查本地配置与持久化目录

```bash
cd "$CAREERLENS_ROOT"
cat compose.yaml
docker compose config --quiet
```

**检查结果：** 配置检查正常退出，无错误输出。默认 `CAREERLENS_MODE` 为 `local`，浏览器端口为 `127.0.0.1:3000`，数据卷 `careerlens-data` 挂载到容器 `/app/backend/data`。

初次验证可直接使用默认配置。需要修改宿主机端口时，用编辑器打开文件：

```bash
nano compose.yaml
```

例如将端口映射改成 `"127.0.0.1:3100:3000"`，浏览器随后访问 `http://127.0.0.1:3100`；容器内仍使用 3000，`FRONTEND_BASE_URL` 保持原值。保存后再次运行 `docker compose config --quiet`。

本地 Docker 的模型配置通过启动后的“模型设置”页面保存。公开网站使用独立的 `.env.hosted` 和 `compose.hosted.yaml`，按[网站部署指南](网站部署指南.md)填写域名、邮件、认证和模型参数。

### 步骤 3：构建镜像并启动服务

```bash
cd "$CAREERLENS_ROOT"
docker compose build
docker compose up -d --wait --wait-timeout 180
docker compose ps
```

首次构建需要联网下载依赖、字体、Chromium 和模型。`build` 成功后再执行启动命令；如构建失败，按本章末尾的错误表处理，再重试失败步骤。

**检查结果：** 应用容器状态为 `healthy`。应用首次启动会创建数据目录、恢复镜像内的语义模型并初始化 SQLite，无需手动导入 SQL。

### 步骤 4：检查数据库与访问入口

```bash
docker compose exec -T careerlens python -c \
  'from pathlib import Path; p=Path("/app/backend/data/resume_matcher.db"); assert p.is_file(), "数据库尚未创建"; print("SQLite 已创建:", p)'
curl -f http://127.0.0.1:3000/api/v1/health
docker compose logs --tail=100 careerlens
```

**检查结果：** 数据库文件存在，健康接口返回 `{"status":"healthy"}`。若调整了端口，请同步修改上述 `curl` 地址。

打开 **http://127.0.0.1:3000**，本地模式无需账号。接口文档为 **http://127.0.0.1:3000/docs**。完成后按本文“功能验证流程”检查主要功能。

停止、重新启动及修改源码后的重建：

```bash
docker compose stop
docker compose start
# 仅在修改源码或升级版本后执行
docker compose up --build -d
```

`docker compose down` 移除容器和网络，但保留数据卷。常规停止和升级保留数据卷；备份与恢复见本文对应章节。

## 方法二 本地源码安装与运行

### 步骤 1：安装 Node.js 与 npm

以下命令适用于 macOS、Linux 和 WSL2 Ubuntu。使用 [nvm 官方安装器](https://github.com/nvm-sh/nvm#installing-and-updating)准备 Node.js，然后选择与生产构建一致的版本；npm 随 Node.js 安装。

```bash
curl -fsSL https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.7/install.sh | bash
if [ -n "${XDG_CONFIG_HOME:-}" ]; then
  export NVM_DIR="$XDG_CONFIG_HOME/nvm"
else
  export NVM_DIR="$HOME/.nvm"
fi
. "$NVM_DIR/nvm.sh"
nvm install 22.23.2
nvm use 22.23.2
node --version
npm --version
```

**检查结果：** Node.js 显示 `v22.23.2`，npm 正常显示版本号。已有 Node.js 22 的环境可以直接检查版本，无需重复安装。新终端需要再次选择环境时执行 `nvm use 22.23.2`。

### 步骤 2：安装 uv 与 Python

uv 管理项目虚拟环境和 Python 依赖。以下使用 [uv 官方版本化安装方式](https://docs.astral.sh/uv/getting-started/installation/)和 [Python 安装命令](https://docs.astral.sh/uv/guides/install-python/)：

```bash
curl -LsSf https://astral.sh/uv/0.12.10/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
uv --version
uv python install 3.13.15
uv python find 3.13
```

**检查结果：** uv 显示 `0.12.10`，最后一条命令返回 Python 3.13 的可执行文件路径。后续统一使用 `uv run --frozen python` 调用项目解释器；不要求改动系统默认 `python3`。

### 步骤 3：复制并修改配置文件

先从示例创建本机配置；已有配置文件时保留原文件。

```bash
cd "$CAREERLENS_ROOT"
if [ ! -f app/apps/backend/.env ]; then
  cp app/apps/backend/.env.example app/apps/backend/.env
fi
if [ ! -f app/apps/frontend/.env.local ]; then
  cp app/apps/frontend/.env.example app/apps/frontend/.env.local
fi
nano app/apps/backend/.env
```

在编辑器中确认或修改以下后端参数。API Key 暂时留空，可在安装完成后通过“模型设置”配置 AI。

```dotenv
CAREERLENS_MODE=local
DATA_DIR=./data
FRONTEND_BASE_URL=http://127.0.0.1:3000
CORS_ORIGINS=["http://localhost:3000","http://127.0.0.1:3000"]
REQUEST_TIMEOUT_SECONDS=240
PDF_MAX_CONCURRENCY=1
LLM_API_KEY=
```

保留示例中的 `LLM_PROVIDER` 和 `LLM_MODEL`；接入模型时再按提供商同步修改它们，并填写 `LLM_API_BASE`（如有）和真实密钥。`DATA_DIR=./data` 在本指南的后端目录启动方式下指向 `app/apps/backend/data/`。`nano` 中按 Ctrl+O、Enter 保存，Ctrl+X 退出。

再打开前端配置：

```bash
nano app/apps/frontend/.env.local
```

确认以下内容并保存：

```dotenv
BACKEND_ORIGIN=http://127.0.0.1:8000
NEXT_PUBLIC_API_URL=/
NEXT_PUBLIC_REQUEST_TIMEOUT_MS=240000
```

**检查结果：** 后端 `.env` 与前端 `.env.local` 均已创建；前后端使用一致的超时设置，分别为 240 秒和 240000 毫秒。完整参数含义见[配置与依赖说明](配置与依赖说明.md)。这些本机配置已由 Git 忽略，不进入源码交付包。

### 步骤 4：安装后端依赖并检查配置

```bash
cd "$CAREERLENS_ROOT/app/apps/backend"
uv sync --frozen --extra dev
uv run --frozen python --version
uv run --frozen python -c \
  'import fastapi, sqlalchemy, playwright; print("后端核心依赖导入成功")'
uv run --frozen python -c \
  'from app.config import settings; print("数据目录:", settings.data_dir.resolve()); print("打印地址:", settings.frontend_base_url)'
```

**检查结果：** 生成后端 `.venv/`，Python 显示 3.13，核心依赖可导入，数据目录和打印地址与上一步配置一致。`--frozen` 按 `uv.lock` 安装；`--extra dev` 同时安装测试工具。无需手动激活虚拟环境。

### 步骤 5：安装 Chromium 与中文字体

macOS 安装 Chromium：

```bash
cd "$CAREERLENS_ROOT/app/apps/backend"
uv run --frozen python -m playwright install chromium
```

Ubuntu / WSL2 Ubuntu 同时安装浏览器系统库和中文字体：

```bash
cd "$CAREERLENS_ROOT/app/apps/backend"
uv run --frozen python -m playwright install --with-deps chromium
sudo apt-get install -y fonts-noto-cjk
```

安装完成后测试浏览器能否启动：

```bash
uv run --frozen python -c \
  'from playwright.sync_api import sync_playwright; p=sync_playwright().start(); b=p.chromium.launch(headless=True); b.close(); p.stop(); print("Chromium 启动成功")'
```

**检查结果：** 输出“Chromium 启动成功”。该浏览器用于 PDF 导出；系统已有 Chrome 不会替代 Playwright 对应版本的安装。

### 步骤 6：初始化数据库并核对业务表

首次安装时执行：

```bash
cd "$CAREERLENS_ROOT/app/apps/backend"
uv run --frozen python -m app.scripts.career_data init
```

**检查结果：** 输出“数据库已初始化。未写入示例材料。”，默认生成 `data/resume_matcher.db`。SQLite 随 Python 使用，无需安装 MySQL、创建数据库账号或手动执行 `data/schema.sql`。

检查文件与业务表：

```bash
uv run --frozen python - <<'PYDB'
import sqlite3
from app.config import settings
path = settings.sqlite_path.resolve()
assert path.is_file(), f"数据库不存在：{path}"
with sqlite3.connect(path) as connection:
    tables = {row[0] for row in connection.execute(
        "SELECT name FROM sqlite_master WHERE type='table'"
    )}
assert {"resumes", "jobs", "match_records", "rewrite_records"} <= tables
print("数据库检查通过：", path)
print("数据表：", ", ".join(sorted(tables)))
PYDB
```

准备演示数据时，可选执行以下命令，将明确标注的虚构简历与岗位写入本地库：

```bash
uv run --frozen python -m app.scripts.career_data init --demo
```

初始化命令可重复执行；已有项目先备份数据，再升级和初始化。网站模式的认证及账号数据库由应用启动流程管理，不通过本地示例命令为网站账号添加数据。

### 步骤 7：下载本地语义模型

```bash
cd "$CAREERLENS_ROOT/app/apps/backend"
uv run --frozen python -m app.scripts.prepare_embeddings
```

**检查结果：** 命令正常完成并报告模型准备结果。固定版本的模型与 tokenizer 下载约 135 MB，存放在 `DATA_DIR` 下的模型目录中；已完成且校验通过的文件可复用。

下载失败时，先继续安装前端并验证编辑、规则匹配和文档导出，待网络恢复后重跑此步骤。模型下载不需要 AI API Key。

### 步骤 8：安装前端依赖

```bash
cd "$CAREERLENS_ROOT/app/apps/frontend"
npm ci --no-audit --no-fund
npm ls next react react-dom --depth=0
```

**检查结果：** `node_modules/` 创建完成，版本列表包含 Next.js `16.3.4`、React / React DOM `19.2.8`，没有缺失依赖错误。`npm ci` 严格依据 `package-lock.json` 安装，并重新生成当前前端目录下的依赖目录。

### 步骤 9：启动并验证安装结果

回到项目根目录，在终端一执行：

```bash
cd "$CAREERLENS_ROOT"
bash scripts/dev.sh
```

保持终端运行。在**终端二**进入同一个项目根目录并检查：

```bash
export CAREERLENS_ROOT="$(pwd)"
curl -f http://127.0.0.1:8000/api/v1/health
curl -f http://127.0.0.1:3000/api/v1/health
tail -n 30 .local/logs/backend.log .local/logs/frontend.log
```

**检查结果：** 两个健康接口均返回 `{"status":"healthy"}`；后端日志出现 `Application startup complete`，前端出现 `Ready`。第二个接口同时验证前端到后端的代理链路。

| 入口 | 地址 |
| --- | --- |
| 应用，本地模式无需账号 | http://127.0.0.1:3000 |
| API 文档 | http://127.0.0.1:8000/docs |
| 健康检查 | http://127.0.0.1:8000/api/v1/health |

打开应用，关闭“AI 辅助”，按下文“功能验证流程”完成一次示例简历与岗位操作。完成模型配置后再验证 AI 生成功能。在终端一按 Ctrl+C 停止前后端，重新执行 `bash scripts/dev.sh` 即可启动。

### 已有环境的一键安装

完成环境准备和配置文件创建后，可用以下命令代替步骤 4 至步骤 8 的依赖及数据准备操作：

```bash
cd "$CAREERLENS_ROOT"
bash scripts/setup.sh
bash scripts/dev.sh
```

Linux 仍需按步骤 5 补齐 Chromium 系统库和中文字体。一键脚本不替代这些系统级依赖。

### 单独启动与更换端口

默认端口被其他程序使用时，可以分别启动。例如使用后端 8100、前端 3100：

```bash
# 终端一，从项目根目录开始
cd app/apps/backend
FRONTEND_BASE_URL=http://127.0.0.1:3100 \
  uv run --frozen python -m uvicorn app.main:app --host 127.0.0.1 --port 8100
```

```bash
# 终端二，从项目根目录开始
cd app/apps/frontend
BACKEND_ORIGIN=http://127.0.0.1:8100 \
  npm run dev -- --hostname 127.0.0.1 --port 3100
```

浏览器地址为 `http://127.0.0.1:3100`。前端代理和后端打印地址必须同步修改，否则可能出现接口或 PDF 导出失败。

## 配置 AI

本地模式在侧栏打开“模型设置”，选择提供商，填写模型标识、API Key，按需填写 Base URL，然后保存并测试连接。也可以复制 `app/apps/backend/.env.example` 为同目录 `.env`，填写配置并重启后端。

未配置模型时，关闭侧栏“AI 辅助”，先验证编辑和规则诊断。启用远程模型后，所选简历与岗位材料会发送给该服务。网站模式的模型配置由运营者统一管理。

## 功能验证流程

使用 `data/examples/resume.synthetic.txt` 和 `data/examples/jobs.synthetic.json` 中的虚构材料验证，无需个人资料。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 关闭 AI，新建或导入示例简历，编辑并保存 | 左侧出现简历，刷新后内容保留 |
| 2 | 在目标岗位粘贴一份 JD 并保存 | JD 可再次选择，岗位要求可校对 |
| 3 | 选择简历和 JD，执行匹配分析 | 显示要求、已有经历和待补充信息 |
| 4 | 配置模型后打开 AI，再执行诊断和段落改写 | 出现匹配理由及可审阅的正文草稿 |
| 5 | 采纳草稿 | 创建独立定向版，原始简历保留 |
| 6 | 打开“模板与排版”，更换模板、字体和字号 | 预览更新，院校与学历显示在顶部 |
| 7 | 点击“收起上方工具栏”，再点击展开或按 Esc | 上方区域整体收起，恢复后排版设置保留 |
| 8 | 保存并导出 PDF、Word | 文件可打开，PDF 保留所选版式，Word 内容可编辑 |
| 9 | 查询实时岗位，展开 JD 和统计 | 显示来源及样本信息，保存的 JD 可用于诊断 |

自动验证本地完整 HTTP 流程：

```bash
python3 scripts/smoke.py
# Docker 模式通过前端端口访问 API
python3 scripts/smoke.py --base-url http://127.0.0.1:3000
```

脚本创建虚构测试记录，结束时仅清理这些记录；PDF 和结果保存在 `.local/qa/`。完整测试与生产构建命令见[验证说明](验证说明.md)。

## 数据备份与恢复

源码运行的数据默认在 `app/apps/backend/data/`，包括 SQLite 数据库、模型缓存、配置和加密密钥。自定义 `DATA_DIR` 后使用指定目录。备份时停止服务，复制整个数据目录，以便同时保留数据库和凭据解密所需文件。

```bash
# 源码模式：先在启动终端按 Ctrl+C
career_backup_dir="$(mktemp -d "$HOME/careerlens-backup.XXXXXX")"
cp -R app/apps/backend/data "$career_backup_dir/data"
```

Docker 模式：

```bash
mkdir -p backups
docker compose stop
docker compose run --rm --no-deps --entrypoint tar \
  -v "$PWD/backups:/backup" careerlens \
  -czf /backup/careerlens-data.tar.gz -C /app/backend/data .
docker compose start
```

每次使用新的备份文件名。恢复时先停止服务，在独立目录或新数据卷中解压备份，令应用使用恢复后的数据目录；核对简历、岗位与模型设置后再正式切换。网站模式还需备份 `.env.hosted`，操作见[网站部署指南](网站部署指南.md)。

## 常见问题

| 现象 | 处理方法 |
| --- | --- |
| `command not found: uv` | 执行 `export PATH="$HOME/.local/bin:$PATH"` 后重试 `uv --version`；仍失败则重跑 uv 安装步骤 |
| `nvm: command not found` / 找不到 `node` | 加载安装目录下的 `nvm.sh`，执行 `nvm use 22.23.2`，再检查 `node --version` 和 `npm --version` |
| `git clone` 提示 `Repository not found` | 核对仓库账号访问权限；也可直接使用交付 ZIP 安装 |
| `ENOENT ... package.json` / 找不到 `pyproject.toml` | 当前目录错误。前端安装在 `app/apps/frontend/`，后端在 `app/apps/backend/`，重新检查 `CAREERLENS_ROOT` |
| `.env` 解析或 `ValidationError` | 检查参数名、整数值和 `CORS_ORIGINS` JSON 数组；在后端目录运行步骤 4 的配置检查命令 |
| `EACCES` / `Permission denied`（依赖目录） | 将源码解压到当前用户拥有的目录后安装；npm 与 uv 依赖安装使用普通用户账号 |
| `npm ci` 提示清单与锁文件不一致 | 使用同一版本的 `package.json` 和 `package-lock.json`，从完整交付包恢复后重试；不要通过删除锁文件跳过校验 |
| `uv sync --frozen` 提示锁文件缺失 | 核对完整源码包内的 `uv.lock` 是否存在，重新解压完整包；依赖清单和锁文件应来自同一次提交 |
| `Could not resolve host` / `ETIMEDOUT` / HTTP 502 | 检查依赖服务网络连接，配置可用代理后重试失败步骤；诊断命令见下方 |
| `Cannot connect to the Docker daemon` | 启动 Docker Desktop；Ubuntu 检查 `sudo systemctl status docker` |
| Docker socket `permission denied` | Ubuntu 使用 `sudo docker ...`；不要修改为所有用户可写的 socket 权限 |
| Docker 构建 `no space left on device` | 检查宿主机磁盘及 Docker 分配的磁盘空间，增加容量后重试 |
| `unable to open database file` / `readonly database` | 核对 `DATA_DIR` 和目录写权限，确保在后端目录运行，保留原数据并参照下方检查命令 |
| Python 版本不匹配 | 安装 Python 3.13；在后端目录运行 `uv sync --frozen --extra dev` |
| 端口占用 | 查看 3000 / 8000 端口的进程归属，或按上面的双终端方式换端口 |
| 页面打开但接口失败 | 检查后端健康接口与日志，核对 `BACKEND_ORIGIN` |
| Chromium 不存在 | 后端目录运行 `uv run --frozen python -m playwright install chromium`；Linux 补装系统依赖 |
| PDF 缺字或导出失败 | 安装 Noto CJK 字体，检查 `FRONTEND_BASE_URL` 可从后端访问，查看后端日志 |
| 语义模型下载失败 | 后端目录运行 `uv run --frozen python -m app.scripts.prepare_embeddings`；确认可以访问 Hugging Face |
| AI 调用失败或超时 | 测试模型连接，核对 Key、模型名及 Base URL；超时需同时调整前后端配置，见配置说明 |
| 前端构建无法下载字体 | 确认构建环境可访问 Google Fonts；为构建进程配置可用的网络代理后重试 |
| 安装或构建内存不足 | 增加可用内存或交换空间，避免同时运行多个构建任务 |
| 岗位搜索为空或来源暂不可用 | 调整关键词、切换来源，或手动粘贴 JD |
| 保存返回版本冲突 | 保留当前修改，读取最新版本后合并，避免覆盖其他页面已保存的内容 |
| 重新启动后数据不见 | 核对 `DATA_DIR`、容器卷和运行模式；本地卷与网站卷分别保存数据 |

部署配置和运行日志中的真实凭据、邮箱与简历属于运行数据，不应加入源码仓库或交付包。

### 安装错误的定位命令

先核对当前目录、磁盘与下载服务。以下均可在项目根目录执行：

```bash
pwd
df -h .
curl -I --connect-timeout 10 --max-time 20 https://pypi.org/simple/
curl -I --connect-timeout 10 --max-time 20 https://registry.npmjs.org/
curl -I --connect-timeout 10 --max-time 20 https://huggingface.co/
```

若本机已配置 HTTP 代理，将下方地址替换为实际代理地址，在当前终端设置后重试下载。WSL2 的代理地址应为其能够访问的地址。Docker 构建还需检查 Docker 自身的代理配置；容器中的 `127.0.0.1` 指向容器自身。

```bash
export HTTPS_PROXY=http://127.0.0.1:7890
export HTTP_PROXY="$HTTPS_PROXY"
export https_proxy="$HTTPS_PROXY"
export http_proxy="$HTTP_PROXY"
export NO_PROXY=localhost,127.0.0.1,::1
export no_proxy="$NO_PROXY"
```

检查后端数据目录是否可写：

```bash
cd "$CAREERLENS_ROOT/app/apps/backend"
uv run --frozen python - <<'PYDIR'
import os
from app.config import settings
p = settings.data_dir.resolve()
print("数据目录：", p)
print("目录存在：", p.is_dir())
print("目录可写：", os.access(p, os.W_OK) if p.exists() else False)
PYDIR
```

`DATA_DIR` 改为其他目录后，应先创建对应目录，再运行初始化命令。查错时保存失败命令与末尾错误信息；配置排查仅输出路径等必要信息，不输出 API Key。
