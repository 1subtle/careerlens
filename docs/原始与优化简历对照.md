## 5. 逐项变化与事实核对

| 原文内容 | 优化表述 | 修改类型 | 原文依据 / 判断 |
| --- | --- | --- | --- |
| “我主要负责和问卷有关的工作。我先设计了问卷” | “我负责问卷设计与数据收集” | 表达调整 | 原文明确负责、设计与收集；未升级为项目负责人 |
| “收集了120份有效回答” | “回收120份有效问卷” | 表达调整 | 数量 120 保留，未增加样本量或回收率 |
| “之后我用Python做数据清洗” | “并使用Python进行数据清洗” | 表达调整 | 工具和动作相同，未加入 SQL、建模等新技能 |
| “比较了不同年级学生在需求方面的差异” | “以分析不同年级学生的需求差异” | 表达调整 | 分析对象和范围相同 |
| “最后把这些内容整理成了一份调研报告” | “最终形成调研报告” | 表达调整 | 保留实际交付物，未添加业务采纳或绩效指标 |
| 身份、教育、首个项目、技能 | 保持原文 | 未修改 | 本次只针对一个段落 |

改进集中在职责、方法、分析对象和交付物的组织，使段落更紧凑。已有 120 份回答属于原始合成事实，不是改写生成的量化成果。本例没有追加本人事实，不能引用另一次 smoke 测试“补充 SQL 后 71.4→85.7”的结果作为本例分数变化。

## 6. 系统演示方式

1. 在独立测试工作区导入原始全文，标题加“课堂对照示例”，校对项目边界后保存。
2. 创建并校对 E3 的虚构目标 JD。关闭 AI 可先演示规则诊断与人工核对。
3. 选中校园数字服务调研段落展示原文与历史改写。直接展示本文件时，标注“2026-09-08 历史调用结果”；若现场重新生成，则记录现场时间、模型与实际输出，不要求逐字一致。
4. 在系统内重新生成草稿并实际采纳时，应观察新版本、原稿和修改记录，再执行同岗复评。本文已排好的全文只是对照材料，不替代系统中的实际采纳记录。
5. 对照检查 120、Python、年级差异和调研报告是否保留；确认没有新增 SQL 应用、Tableau、上线、留存增长或其他未提供事实。
