# CareerLens 网站部署指南

网站模式使用邮箱验证码登录，每个账号拥有独立业务数据。Docker Compose 启动应用与 Caddy，Caddy 自动申请和续期 HTTPS 证书。

## 部署准备

准备安装了 Docker Compose v2 的 Linux 服务器、已解析到服务器的域名、可发送邮件的 SMTP 账号和模型 API 凭据。开放 TCP 80、443；UDP 443 用于 HTTP/3，可按网络环境开放。构建建议至少 4 GB 可用内存；也可在独立构建机生成镜像后传入服务器。

从仓库或源码包取得项目，在根目录复制配置：

```bash
cp .env.hosted.example .env.hosted
python3 -c 'import secrets; print(secrets.token_urlsafe(48))'
```

将生成的随机字符串写入 `CAREERLENS_AUTH_SECRET`，并填写：

| 配置 | 说明 |
| --- | --- |
| `CAREERLENS_DOMAIN` | 域名，不含协议与路径，例如 `career.example.com` |
| `CAREERLENS_AUTH_SECRET` | 至少 32 字符的固定随机密钥，后续升级保持一致 |
| `CAREERLENS_SMTP_HOST/PORT` | 邮件服务器与端口 |
| `CAREERLENS_SMTP_USERNAME/PASSWORD` | SMTP 凭据，两项同时填写 |
| `CAREERLENS_SMTP_FROM` | 邮件服务认可的发件地址，可使用 `CareerLens <login@example.com>` |
| `CAREERLENS_SMTP_SECURITY` | 587 通常为 `starttls`，465 通常为 `ssl` |
| `LLM_PROVIDER/MODEL/API_KEY/API_BASE` | 运营者提供的模型服务 |
| `CAREERLENS_GITHUB_URL` | 可选，网站上展示的项目仓库链接 |

`.env.hosted` 由 Compose 读取，不会打包到镜像。值含 `$` 或 `#` 时使用单引号包裹，避免 Compose 插值和注释解析改变凭据。不要在公开日志中输出完整展开配置。

## 启动与检查

```bash
docker compose --env-file .env.hosted -f compose.hosted.yaml config --quiet
docker compose --env-file .env.hosted -f compose.hosted.yaml up --build -d
docker compose --env-file .env.hosted -f compose.hosted.yaml ps
docker compose --env-file .env.hosted -f compose.hosted.yaml logs --tail=100
```

等待应用显示 `healthy`，访问配置的 HTTPS 域名，再验证健康接口：

```bash
curl -f https://career.example.com/api/v1/health
```

将示例域名替换为实际域名。网站仅经 Caddy 暴露入口，应用端口保留在 Compose 网络内。若需要额外域名跳转，可在 `deploy/Caddyfile` 中添加对应重定向并配置 DNS。

依次验证：发送验证码并登录、新建简历、保存 JD、运行匹配、生成并采纳改写、导出 PDF 与 Word、退出后重新登录。使用两个测试账号检查简历和历史记录彼此隔离。AI 服务需实际配置成功才能验证生成与积分扣减。

## 积分与充值

`CAREERLENS_SIGNUP_CREDITS` 默认给新验证邮箱发放 20 积分。成功的 AI 生成操作消耗积分，失败操作释放预留积分；余额和流水可在账户页面查看。

充值默认关闭。接入微信 Native 支付前，按 `.env.hosted.example` 配齐商户、签名、平台验签及回调参数，并将 `CAREERLENS_CREDIT_PACKAGES` 设置为 JSON 数组。套餐字段为 `id`、`name`、`credits`、`amount_fen` 和 `currency`，金额单位为整数分，币种为 `CNY`。价格由运营者确定；启用前应完成创建订单、扫码支付、验签回调与重复通知验证。

## 升级、备份与恢复

升级前停止应用并备份数据，保存当前镜像和提交版本。认证、业务数据库及加密密钥均在 `/app/backend/data`，使用 `hosted-data` 持久卷；HTTPS 证书保存在 Caddy 卷。

```bash
mkdir -p backups
docker compose --env-file .env.hosted -f compose.hosted.yaml stop careerlens
docker compose --env-file .env.hosted -f compose.hosted.yaml run --rm --no-deps \
  --entrypoint tar -v "$PWD/backups:/backup" careerlens \
  -czf /backup/hosted-data.tar.gz -C /app/backend/data .
cp .env.hosted backups/env.hosted.backup
chmod 600 backups/env.hosted.backup
```

为每次备份使用独立目录或文件名，将备份保存在受限位置。接着更新源码并启动：

```bash
git pull --ff-only
docker compose --env-file .env.hosted -f compose.hosted.yaml up --build -d
```

应用启动时自动执行数据库迁移。升级后重新检查健康状态、账号登录、已有数据与导出。需要回退时，使用升级前镜像和与其配套的数据备份，不将迁移后的数据库直接交给旧版本。

恢复至一套独立部署时，准备原 `.env.hosted` 和备份，先构建镜像，再将备份写入该部署的新数据卷：

```bash
docker compose --env-file .env.hosted -f compose.hosted.yaml build
docker compose --env-file .env.hosted -f compose.hosted.yaml run --rm --no-deps \
  --entrypoint tar -v "$PWD/backups:/backup:ro" careerlens \
  -xzf /backup/hosted-data.tar.gz -C /app/backend/data
docker compose --env-file .env.hosted -f compose.hosted.yaml up -d
```

恢复命令面向空卷；已有生产卷应先完整备份，并在独立部署验证恢复结果。SQLite 部署保持单个应用实例，共享卷多副本不在当前运行方案内。

## 故障处理

| 现象 | 检查与处理 |
| --- | --- |
| HTTPS 未就绪 | 核对 DNS、公网 80/443、防火墙及 Caddy 日志 |
| 502 | 检查应用健康状态，查看前后端启动日志，确认镜像构建完成 |
| 验证码未收到 | 核对 SMTP 端口、加密方式、发件地址认证及垃圾邮件箱 |
| 启动提示认证配置错误 | 核对随机密钥长度、HTTPS 域名与 SMTP 成对配置 |
| 登录后写入失败 | 核对网站公网地址与实际浏览器地址一致，检查反向代理头和 Cookie |
| AI 不可用 | 核对模型配置、出站网络及账户余额；查看后端错误日志 |
| PDF 超时或进程退出 | 保持 `PDF_MAX_CONCURRENCY=1`，检查可用内存与容器内前端访问 |
| 升级后找不到数据 | 检查 Compose 项目名和持久卷，确认未切换到本地模式的数据卷 |
