# CareerLens 网站部署指南

同一份源码提供两种模式：`local` 保留本机个人工作区；`hosted` 提供公开入口、邮箱验证码登录与每用户独立工作区。默认使用 `local`，无需邮件或账号服务。

初期使用免费服务，可按[免费服务部署](免费服务部署.md)选择服务器、子域名与邮件配置。

## 本地使用

安装 Docker Engine / Docker Desktop 及 Compose v2，在源码根目录运行：

```bash
docker compose up --build -d
```

打开 `http://127.0.0.1:3000`。也可以按根目录 README 使用 Python、Node.js 和 uv 运行源码。

## 网站部署

准备一台可运行 Docker Compose 的 Linux 服务器、域名，以及可以发送验证码的 SMTP 服务。服务器需要持久磁盘；此版本使用本机 SQLite 文件，不适合部署到无持久磁盘的静态托管或无状态函数平台。

将域名的 DNS 记录指向服务器，开放 80 和 443 端口。在服务器放置源码，然后复制配置：

```bash
cp .env.hosted.example .env.hosted
chmod 600 .env.hosted
python3 -c 'import secrets; print(secrets.token_urlsafe(48))'
```

把生成的随机字符串填入 `.env.hosted` 的 `CAREERLENS_AUTH_SECRET`，再填写：

| 变量 | 内容 |
| --- | --- |
| `CAREERLENS_DOMAIN` | 站点域名，不含 `https://` 和路径 |
| `CAREERLENS_AUTH_SECRET` | 至少 32 字符的随机认证密钥 |
| `CAREERLENS_SMTP_HOST` / `PORT` | 邮件服务地址和端口 |
| `CAREERLENS_SMTP_USERNAME` / `PASSWORD` | 邮件服务提供的用户名和密码／授权码 |
| `CAREERLENS_SMTP_FROM` | 已验证的发件人，例如 `CareerLens <login@your-domain.com>` |
| `CAREERLENS_SMTP_SECURITY` | 587 端口通常为 `starttls`，465 端口为 `ssl` |
| `CAREERLENS_GITHUB_URL` | 可选，自己的 CareerLens 开源仓库地址 |
| `LLM_PROVIDER` / `LLM_MODEL` / `LLM_API_BASE` / `LLM_API_KEY` | 站点使用的 AI 服务配置，变量名均保留 `LLM_` 前缀 |
| `CAREERLENS_SIGNUP_CREDITS` | 每个已验证邮箱的一次性免费积分，默认 20；更改后用于新账号 |

邮件域名按服务商要求设置 SPF、DKIM 等记录。页面不会显示验证码，也不会用假成功替代发信失败。

```bash
docker compose --env-file .env.hosted -f compose.hosted.yaml config --quiet
docker compose --env-file .env.hosted -f compose.hosted.yaml up --build -d
docker compose --env-file .env.hosted -f compose.hosted.yaml logs --tail=100
```

访问 `https://你的域名`。Caddy 根据域名自动申请并续期 HTTPS 证书；应用的 3000 端口和后端 API 不直接公开。[Caddy 官方说明](https://caddyserver.com/docs/automatic-https)

`CAREERLENS_PUBLIC_URL` 由部署文件生成，用于登录安全校验。`FRONTEND_BASE_URL` 是 PDF 渲染访问的内部地址，保持 `http://127.0.0.1:3000`。API 仅信任容器内的 Next.js 代理，Caddy 覆盖外部传入的转发头。[FastAPI 代理说明](https://fastapi.tiangolo.com/advanced/behind-a-proxy/)

## 邮箱登录与账号数据

首次验证邮箱会自动创建账号，以后用同一邮箱登录同一工作区。验证码有效期 10 分钟，60 秒后可重新发送，连续错误及发送频率均有限制。会话通过 HttpOnly Cookie 保存，退出会撤销会话。

网站数据卷中的文件结构：

```text
data/
├── auth.sqlite                  # 邮箱账号、验证码哈希、会话哈希
├── users/
│   └── <账号 UUID>/workspace.sqlite
└── ...                          # 运营者配置、密钥与公共模型缓存
```

每个账号的简历、照片、已保存 JD、匹配诊断、改写及旧版接口数据均落在自己的数据库。网站的 `hosted-data` 卷与本地卷独立；本地已有简历不会自动归给首个注册账号。

网站 AI 服务由运营者通过环境变量配置，普通账号不能读取或修改服务器密钥与全局设置。PDF 与 Word 导出也需要登录，并使用当前账号的简历。

首次验证邮箱赠送 20 积分，同一邮箱重复登录不会重复领取。积分保存在账号数据库，独立于个人工作区，重置简历数据不会恢复积分。升级前已有账号会一次性补发初始积分。

每次成功的 AI 模型生成扣除 1 积分；完整润色包含内容生成、事实核验，必要时还有重新生成，因此可能消耗多积分。单次模型调用失败或取消会退还该次预扣积分；已经成功完成的生成与核验仍计费。并发扣分通过数据库原子更新，余额不足时停止后续模型调用。规则诊断、手动编辑和文件导出不扣积分。`GET /api/v1/auth/credits` 返回当前余额和赠送规则。

## 更新与备份

更新源码前，先停止应用并备份数据；不要使用 `down -v` 删除数据卷。

```bash
mkdir -p backups
docker compose --env-file .env.hosted -f compose.hosted.yaml stop careerlens
docker compose --env-file .env.hosted -f compose.hosted.yaml run --rm --no-deps \
  --entrypoint tar -v "$PWD/backups:/backup" careerlens \
  -czf /backup/careerlens-data.tar.gz -C /app/backend/data .
docker compose --env-file .env.hosted -f compose.hosted.yaml up --build -d
```

另外保管 `.env.hosted`。认证密钥和模型密钥与数据库一起按私人数据管理，不进入 Git。多次备份请使用不同文件名。

当前部署形态为单台服务器加持久磁盘。若后续需要多副本横向扩容，再将账号与工作区迁移到共享数据库及对象存储。

## 发布到 GitHub

根目录 `LICENSE` 与上游 `app/LICENSE` 均采用 Apache-2.0；保留 `UPSTREAM.md` 和第三方署名。公开仓库应包含源码、锁文件、部署文件及配置示例；`.env`、个人数据库、上传与导出文件均被忽略。

创建自己的空仓库后，将它设为 `origin`；`upstream` 继续指向原 Resume Matcher，便于跟踪来源。把真实仓库地址填入 `CAREERLENS_GITHUB_URL` 后，网站会显示对应的开源入口。
