## 1. 设计结论与依据

CareerLens 的界面应围绕“整理真实经历—理解岗位要求—核对匹配证据—形成定向版本”组织。首页已有连续简历编辑、岗位录入、诊断优化和实时岗位四个入口，适合保留这一结构，通过清晰的状态、来源和下一步操作连接完整求职准备流程。

本方案以当前前端源码、样式和测试用例为依据，使用 ui-ux-pro-max 技能核对 Next.js 客户端边界、错误汇总和字段错误关联；W3C 相关链接沿用既有设计记录，本轮未重新联网查验。工作区采用现有奶油色与紫色视觉，不另建一套与项目脱节的界面风格。

本文的“已实现”表示已在源码中发现相应实现；“设计要求”表示后续开发和验收目标。设计说明依据源码核查，项目本轮另执行了70项前端、133项后端专项回归，结果见[测试报告](测试报告.md)。本轮没有运行浏览器视觉或屏幕阅读器检查。用户角色和行为路径基于产品用途形成，尚未经用户访谈验证。

## 2. 用户与体验目标

主要用户为准备实习、校招或下一份工作的个人求职者。用户可能已有简历，也可能只有零散项目记录；可能有明确 JD，也可能先探索岗位方向。界面需要同时支持这两种起点。

表 2 用户与体验目标

| 使用情境 | 用户要完成的事 | 界面需要给出的支持 |
| --- | --- | --- |
| 第一次整理简历 | 将经历变成可编辑文档 | 打开即编辑，导入为可选入口；章节完整、原文可核对 |
| 已有目标岗位 | 判断经历如何回应 JD | 并列展示岗位原文、简历证据和判断依据 |
| 方向尚不明确 | 找到值得进一步了解的岗位方向 | 方向建议附经历引用，能够继续查找实时岗位 |
| 同时准备多个岗位 | 比较差异并保留不同版本 | 同一简历比较 2—5 份 JD，改写采纳后生成独立版本 |
| 手机查岗位、电脑改简历 | 在窄屏完成查找与核对 | 页面不横向溢出，筛选和关键操作保持可触达 |

设计目标是让用户知道当前使用哪份简历和 JD、哪些结论来自规则或模型、每项判断依据在哪里，以及下一步应补充什么。分数和图表服务于判断；主要成果是可核对的经历表达与可继续使用的文档。

### 3.2 导航规则

已实现：主导航通过 `aria-current` 指示当前面板，版本按钮通过 `aria-pressed` 标记选择；手机端以版本下拉框替代长列表。操作执行期间禁用切页；简历和 JD 编辑有未保存内容时通过浏览器确认框拦截离开，并注册关闭页面前的提示。补充事实、核对选择和比较选择尚未接入该保护，面板卸载后不保留。

设计要求：为面板、简历和诊断记录增加可恢复的 URL 状态，使刷新、返回及分享定位到预期内容；实施前应同步确定敏感记录的访问边界。切换结果视图后将焦点移动到结果标题，或提供“跳到分析结果”的链接。当前 AI 选择仅在本次工作区挂载期间保留，不能描述为跨刷新偏好保存。

### 3.3 网站访问与会话切换

网站匿名访问显示公开首页，点击“在线使用”进入邮箱验证。客户端只在服务端声明邮件登录可用时显示登录表单，六位验证码支持自动填充、到期提示、重发倒计时和更换邮箱。首页的 GitHub 地址是“本地部署”仓库外链，不是第三方登录。

验证成功后加载个人工作区。退出、会话过期或跨标签页身份变化时，系统丢弃受保护组件树、取消旧业务请求并清理已知简历草稿缓存。网站 `/settings` 展示“账户与服务”，本地模式继续提供模型配置。设计验收需重点观察账号切换后是否出现旧简历闪现，以及失败提示是否提供恢复路径。

## 4. 关键用户路径

### 4.1 有明确 JD 的求职准备

1. 新建或导入简历，核对解析结果，保存个人版本。
2. 粘贴目标 JD，补充岗位名称；按需校对提取出的要求并记住 JD。
3. 选择已保存的简历与 JD，运行目标匹配分析。
4. 阅读 AI 建议与材料覆盖度，逐项核对原文、证据和待确认条件。
5. 选择一段经历，补充本人真实事实，生成并审阅改写。
6. 确认没有新增或夸大经历后，采纳为独立版本；查看、导出或进行同岗复评。

### 4.2 没有明确 JD 的方向探索

保存简历后，用户可在 AI 开启时分析岗位方向。方向结果展示经历引用与准备行动，并提供“查找相关实时岗位”。用户查看外部来源的完整 JD 后记住岗位，再进入具体诊断。已保存岗位推荐只引用工作区现有 JD，不能与实时搜索结果混为一类。

### 4.3 多岗位比较

选择同一简历及 2—5 个已保存岗位后生成横向结果，分别展示 AI 岗位适合度、材料覆盖度、要求状态和条件状态。用户可进入任一岗位核对证据，再返回比较结果。材料变更后保留原快照并提示重新比较，避免把不同材料的结果当成同一次比较。

### 4.4 模型不可用时

已实现的规则路径包括简历解析、岗位要求提取、材料覆盖度诊断、事实整理和本页统计说明。方向分析与已保存岗位推荐依赖 AI，关闭 AI 后相应按钮禁用。本地模式设置页支持模型配置与连接测试，模型未配置时首页给出配置入口；网站模型由运营者配置，账户页不向普通用户提供密钥编辑。AI开关本身仍可能显示开启，应补充“已开启、待配置”的可见状态，并按运行模式提供设置入口或联系运营者的提示。

## 5. 页面设计规格

### 5.1 我的简历：以文档为中心

对应需求：FR-01、FR-02、FR-09、FR-14、FR-16。

顶部工具栏放置版本名称、保存、编辑/预览/排版、导入、PDF、Word 和更多操作。正文采用连续章节，章节导航允许直接跳转到编辑位置；隐藏于导出的章节仍可编辑。教育、工作、项目、技能和自定义章节由现有 `ResumeForm` 复用，避免另建不兼容的数据表单。

表 4 我的简历：以文档为中心

| 区域 | 已实现行为 | 设计要求与验收要点 |
| --- | --- | --- |
| 版本名称 | 最大 120 字符；空名称禁用保存 | 名称过长可编辑和识别，不仅依赖悬停提示 |
| 保存 | 显式保存、支持 ⌘S / Ctrl+S、发送材料 hash 和含排版的 revision | 保存失败保留输入；冲突时给出重新读取与保留草稿路径 |
| 编辑 | 连续章节、长文本自动适配高度 | 光标不因保存或布局变化丢失；完整文字可读 |
| 预览 | 展示当前尚未保存的内容、照片和排版 | 已有简历的工具栏导出会先保存；新建草稿须先显式保存 |
| 导入 | PDF、DOCX、TXT、Markdown；5 MB；文本最多 30,000 字符 | 解析完成返回编辑；模式与警告可见，覆盖当前文档前说明影响 |
| 更多操作 | 原生 `dialog`，排版链接和删除入口 | 弹层关闭后焦点回到触发按钮；删除确认清楚说明关联记录范围 |
| 照片 | 个人信息内上传、更换或移除 PNG/JPG，源文件至多 10 MB | 浏览器居中裁切为 360×480，失败保留原照片；照片不进入 AI 提示词 |
| 排版 | 字号、行距、间距、纸张、页边距及自动排版 | 每份简历独立保存；自动排版保留全部内容，长文档允许多页 |
| PDF/Word 导出 | 已有简历先保存当前内容与排版再下载；未保存新稿的导出按钮禁用 | 保存冲突不得继续导出旧稿；Word 为可编辑文字并嵌入照片 |

### 5.2 目标岗位：先原文，后结构化

对应需求：FR-03。首屏保留岗位名称和 JD 原文两个必填项；公司、城市、薪资、来源和日期放在折叠区。要求抽取与校对为第二层操作，保存时可自动抽取。

每条要求显示名称、普通/优先类别、JD 原文引用和删除操作，最多 60 条。修改 JD 原文后已提取要求失效，界面提示重新提取。没有识别到要求时允许手动添加。已记住 JD 可回填、修改、继续诊断或删除。

设计要求：将空白要求、非法来源 URL、来源引用不匹配等错误定位到具体字段，并以文字说明修复方法。当前必填内容主要通过按钮禁用判断，不能把 `required` 属性存在等同于完整表单验证。保存动作名称保持“记住这份 JD”，完成后反馈“已记住，可用于诊断”。

### 5.3 诊断与优化：结论与证据连续呈现

对应需求：FR-04 至 FR-10。

选择器与分析按钮位于顶部。AI 结果先给简要结论和适合度，再展示适合理由、差距和改进行动；材料覆盖度独立显示。每项规则诊断按“岗位要求—岗位原文—简历证据—判断理由—核对操作”排列。长页面通过明确小标题形成阅读节奏，关键引用保持可见。

图 3 诊断与优化：结论与证据连续呈现

```text

│ 要求 A   [有具体证据]   权重 / 材料贡献                  │

├───────────────────────────────────────────────────────┤
│ 选择段落 → 补充事实 → 原文与建议对照 → 逐句来源         │
│ [ ] 确认内容准确        [采纳并生成独立版本] [拒绝]     │

└───────────────────────────────────────────────────────┘
```

用户核对证据或条件后保存为新的诊断记录；语义候选经历明确标注“尚未计入覆盖度”。选择“有具体证据”或“仅有提及”时应关联材料，候选列表优先展示检索找到的相关经历。学历、经验、到岗与实习时长单列，避免条件状态与材料分数相互替代。人工核对目前沿用原 AI 分析，设计上应说明“规则核对已更新，AI 分析未重新生成”，并保留其原生成时间。

改写区域已提供原文/建议对照、修改类型、逐句来源、待补充事实及确认勾选。对照使用 `del` / `ins` 标记差异；没有实质变化和改动很少时有直接说明。生成与采纳分为两个动作，采纳后显示独立版本、同岗复评和 PDF 导出入口。

设计要求：材料或 JD 变更后保持历史快照提示，禁止基于过期诊断继续采纳；核对后在当前位置显示新记录已保存。未来可增加结果目录以缩短长页面定位，但不改变引用与判断的邻接关系。

### 5.4 实时岗位：来源清晰、样本边界可见

对应需求：FR-11、FR-12。默认检索国家大学生就业服务平台，可切换腾讯招聘及 Jobicy；Jobicy 额外提供全部、中国、美国、欧洲地区选项。筛选条件输入与已提交条件分开保存，翻页使用实际查询条件。

| 岗位列表 | 名称、公司、地点/远程范围、类别、日期；展开后看正文 | 完整 JD 缺失时提示并禁用记住；外链仍可使用 |
| 岗位操作 | 使用并记住 JD、再次使用、查看原文 | 成功后进入目标岗位面板，保留真实来源信息 |
| 分页 | 上一页、下一页、页码、每页上限 | 不将未提交的来源或关键词用于当前结果翻页 |
| 统计 | 默认折叠；按需载入图表，附技能频次表和 JSON 导出 | 只解释本页完整 JD，不将样本比例命名为整个市场趋势 |
| 解读 | 用户问题、AI 解读或规则统计说明 | 显示分析模式和样本数，不能暗示覆盖所有招聘岗位 |

图表包含技能词云、薪资散点图和岗位类别技能占比热力图。词云大小表示包含技能的岗位数；同一岗位对同一技能计一次。薪资按币种和支付周期分组，以区间中点绘图，保留来源薪资文本。热力图显示百分比、类别样本量及高频技能，分母为该类别岗位数。

当前 Jobicy 的来源薪资在 JD 中展示，未送入薪资图表；腾讯来源缺少结构化薪资。这些来源出现薪资空状态时，应说明“当前来源暂无可统计薪资”，并保留原文查看入口。界面还需补充薪资有效数和缺失数；实时页的获取时间与记住 JD 后的入库时间也应分别命名。

图表已有 ARIA 描述、禁用动画及容器尺寸观察；技能频次另有表格。设计要求是补齐薪资与分类技能的可读数据表，让键盘和屏幕阅读器用户无需操作画布提示即可读取精确值。

### 5.5 设置与排版编辑器

对应需求：FR-02、FR-13—16。本地设置页已采用与工作区相近的奶油紫色，内容最大宽度 848 px。模型配置、连接测试和系统状态有明确区域；密钥输入为密码控件，支持密钥管理及危险操作确认。设计要求是让未配置、已保存、测试成功、测试失败分别具有文字状态，避免用单一绿色指示代替实际结果。

排版编辑器仍采用全局 Swiss 风格，桌面有编辑与预览双栏，并保留自动保存及附件相关功能。工作区采用手动保存，PDF/Word 导出前自动保存本次编辑；两处保存机制应分别说明。排版页面的下一步重点是统一品牌、导航和保存反馈；不因统一界面风格而改变简历模板或 PDF 的排版规范。

项目以 [WCAG 2.2 AA](https://www.w3.org/TR/WCAG22/) 作为验收目标，尚未完成合规测试。以下具体要求用于开发与验证，不表示当前页面已经全部满足。

## 9. AI 可信交互与隐私

AI 岗位适合度与材料覆盖度在当前界面中并存。前者展示模型、时间、判断理由和引用；后者说明规则、权重及每条材料贡献。两者必须保留各自名称，不合并为“录用概率”，也不承诺改写必然提高分数。具体评分规则参见[系统设计方案](系统设计方案.md)。

内容核对遵循四项原则：原始引用邻近结论；语义候选须经确认后关联；新增事实由本人确认；采纳改写生成独立版本。已有 UI 为这些动作提供可见说明和确认控件，后续应以完整路径验证，尤其检查历史快照和重复请求。

本地工作区并不等于所有处理都在本地。当前界面有 AI 开关、模型设置及来源标注，但未发现统一的首次 AI 传输告知流程。设计要求是在首次需要向配置的模型服务发送材料前说明发送内容、服务对象和用途，并提供继续、取消及改用规则模式的操作；保存选择应与实际模型服务配置关联。

删除简历和 JD 已有确认提示，说明关联诊断及建议的处理范围；本地设置页另有密钥清理和数据库重置，网站账户页提供退出登录。危险操作应展示具体对象和影响，不以普通保存提示代替。导出的 PDF、Word、诊断 JSON 和岗位样本 JSON 可能包含用户材料，导出说明应提示文件包含的内容，支持用户自行管理下载文件。
