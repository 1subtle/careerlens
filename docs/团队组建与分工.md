## 2. 协作约定

每次变更先关联需求编号，再明确输入输出、影响页面和验收方法。接口变更同时维护请求类型、后端校验及 API 文档；评分、快照或采纳规则变化须记录兼容影响。工作分支按仓库规则使用 `codex/` 前缀或团队已约定名称，提交者使用真实身份；现有 Codex 提交只证明工程变更，不等同于某名学生独立编写。

交叉验收先运行测试，再按关键用例操作。测试失败记录完整错误、触发条件和复验结果。组长在最终打包前检查依赖锁文件、初始化、许可、文档、真实材料与格式清单。
