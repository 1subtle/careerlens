## 数据与功能

| 项目 | 实现 |
| --- | --- |
| 账号隔离 | 每个账号使用 `data/users/<用户ID>/workspace.sqlite`；认证、积分和订单共用认证库，接口按已登录用户限定归属 |
| JD 版本 | 新 JD 从版本 1 开始；编辑必须带 `expected_version`。并发旧版本返回 409，前端保留编辑并提供最新内容供合并 |
| 方向历史 | `direction_history` 保存结果、简历/岗位输入快照、指纹和时间；可列表、查看、导出、删除 |
| 统计历史 | `market_history` 分别保存已有岗位/实时岗位样本、筛选条件、问题和结果；原始材料删除后快照仍可查看 |
| 版本迁移 | 认证库、业务库各有编号迁移与 SHA-256 校验记录。逐版本事务执行，重复启动不重放已应用迁移，文件被改写或数据库版本超前时拒绝启动 |
| 积分流水 | 每次生成记录预留、消费或退回，包含操作和生成标识、变动量、变动后余额。注册赠送与充值也有流水 |
| 旧余额 | 迁移保留现有余额，以“期初余额”入账；历史上没有记录的逐次消费不会补造 |
| 跨库提交 | 持久业务结果与积分结算通过 SQLite ATTACH 参加同一次提交；共同提交或共同回滚 |
| 异常恢复 | 失败/取消释放自己的预留；持久操作有续期与过期恢复，启动及每 60 秒检查遗留预留 |
| 充值订单 | 微信 Native v3；创建请求幂等，保存订单价格与积分快照；订单归属、金额、币种、商户和交易号均在入账时核对 |
| 账户页 | 可用/预留积分、流水分页、订单、微信二维码、到期提示和服务端支付状态刷新 |

跨文件原子性采用持久 SQLite 文件、同一文件系统、DELETE 回滚日志和 FULL 同步，模型与支付网络调用在写事务外完成。SQLite 官方说明：附加数据库的跨文件原子提交要求主库不是内存数据库且不采用 WAL。[SQLite ATTACH](https://www.sqlite.org/lang_attach.html)、[SQLite atomic commit](https://www.sqlite.org/atomiccommit.html)。

只返回临时结果的解析、问答等接口在服务端成功返回前结算；保存型诊断、方向、统计、润色预览/结果、上传解析结果及求职内容生成在业务保存事务中结算。提交后若响应连接断开，已保存结果与账务继续有效。

## 微信支付配置

已实现微信官方公钥模式：商户 RSA 签名、微信响应/回调 RSA 验签、通知 AES-256-GCM 解密、重复通知幂等。二维码由服务端本地生成，不发送给第三方二维码服务。[微信 Native 支付](https://pay.wechatpay.cn/doc/v3/merchant/4012791877)、[签名说明](https://pay.wechatpay.cn/doc/v3/merchant/4012365336)、[微信支付公钥](https://pay.wechatpay.cn/doc/v3/merchant/4012154180)。

暂定套餐已保存在 `deploy/credit-packages.proposed.json`，尚未启用。真实收款需要符合微信支付准入要求的商户主体、APPID、Native 支付权限与凭据，并在正式销售前完善实际调用成本记录和预算限制。当前 `payment_enabled=false`，不展示可支付套餐。配置项位于 `.env.hosted.example`，由 `compose.hosted.yaml` 传入容器：

- `CAREERLENS_CREDIT_PACKAGES`：JSON 套餐数组，包含 `id/name/credits/amount_fen/currency`；金额以整数分表示。
- `CAREERLENS_WECHAT_APPID`、`MCHID`、`MERCHANT_SERIAL`、`MERCHANT_PRIVATE_KEY`、`API_V3_KEY`、`PLATFORM_KEY_ID`、`PLATFORM_PUBLIC_KEY`（均使用前述完整前缀）。
- 回调默认 `https://careerlens.cc/api/v1/billing/wechat/notify`，可用 `CAREERLENS_WECHAT_NOTIFY_URL` 覆盖。

私钥及 API v3 密钥应直接写入服务器私有环境配置，不提交到仓库或对话。现有套餐下架后，已创建订单仍可验签到账。商户后台人工退款需人工对账，本次未接自动退款及积分追回。

## 升级与回退

启动自动升级认证库、操作员库及已有用户业务库。手工检查命令（在后端目录执行）：

```sh
python -m app.migrations status --kind auth --database data/auth.sqlite
python -m app.migrations status --kind business --database data/users/用户ID/workspace.sqlite
```

此次认证库新增列，旧镜像不保证兼容新库。发布应先停止入口流量、等待已有请求结束并冷备数据，再启动新镜像与检查。开放流量前若失败，可保留失败升级副本并恢复刚才的冷备；开放后不得自动恢复旧备份，避免覆盖新充值和新结果，应修复后继续升级。
