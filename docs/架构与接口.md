# 架构与接口

CareerLens 由 Next.js 前端与 FastAPI 后端组成，SQLite 持久化业务数据。浏览器通过同源 `/api/v1` 访问后端；Docker 将前后端放在同一容器，网站模式再由 Caddy 提供 HTTPS。

## 主要模块

| 模块 | 源码位置 | 职责 |
| --- | --- | --- |
| 工作区 | `app/apps/frontend/components/career/` | 简历、JD、匹配、改写、模板与设置交互 |
| 页面与代理 | `app/apps/frontend/app/`、`next.config.ts` | 页面入口、打印页面与同源代理 |
| 业务接口 | `app/apps/backend/app/routers/` | 请求验证、账号边界与业务调用 |
| 业务服务 | `app/apps/backend/app/services/` | 匹配、改写、招聘搜索、语义检索与统计 |
| 模型与提示词 | `app/apps/backend/app/llm.py`、`prompts/` | 提供商适配、请求策略与生成约束 |
| 数据持久化 | `app/apps/backend/app/database.py`、`models.py`、`migrations/` | SQLite、SQLAlchemy 与版本迁移 |
| 网站账户 | `app/apps/backend/app/auth.py`、`hosting.py`、`billing.py` | 验证码、会话、积分和支付 |

## 数据与主要流程

简历保存结构化内容、版本和排版设置。JD 保存原文、来源、岗位要求和采集信息。匹配分析记录当次简历、岗位与证据快照，后续修改不会覆盖历史结果。改写草稿经确认后创建独立简历版本，重复采纳返回同一结果。

规则匹配按岗位要求关联简历经历；语义检索为相关经历提供本地候选；启用 AI 后进一步生成匹配理由、方向建议及段落正文。用户补充的材料随改写请求进入上下文，生成结果经审阅后应用。

PDF 由后端通过 Playwright 访问前端打印页面生成，共用预览版式。Word 通过 python-docx 生成可编辑文档。网站模式为打印请求传递对应身份，按账号读取简历。

本地模式使用默认业务库；网站模式由会话确定用户身份并分配业务数据目录，认证与积分使用独立认证库。启动时执行迁移并恢复未结算积分预留。数据备份必须包含整个数据目录及加密密钥。

## API 入口

运行后的 OpenAPI 为当前接口定义的唯一完整清单：源码模式访问 `http://127.0.0.1:8000/docs`，Docker 访问 `http://127.0.0.1:3000/docs`，JSON 为 `/openapi.json`。

| 接口组 | 用途 |
| --- | --- |
| `/api/v1/health` | 健康状态 |
| `/api/v1/career` | 结构化简历、JD、匹配快照、方向分析、改写与历史 |
| `/api/v1/career/live` | 实时招聘搜索与岗位详情 |
| `/api/v1/resumes` | 原有简历管理、模板打印与文档导出 |
| `/api/v1/config` | 模型设置和连接验证 |
| `/api/v1/auth` | 邮箱验证码、会话与退出 |
| `/api/v1/account` | 账户信息与个人设置 |
| `/api/v1/billing` | 积分、订单与支付通知 |

网站模式的业务接口要求有效会话；写入请求还验证来源。接口字段、状态码及具体路径以运行实例的 OpenAPI 为准。

## 开发与扩展

新增业务能力时，在后端服务层实现规则，通过路由暴露接口，并在前端 `lib/` 中维护请求类型与调用。影响持久化结构的修改需加入迁移；影响改写、版本、账户或积分的修改需覆盖对应事务与隔离测试。运行命令见[验证说明](验证说明.md)。
