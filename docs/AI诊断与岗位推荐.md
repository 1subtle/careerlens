# AI 诊断与岗位推荐

本次修复解决了旧诊断只计算关键词覆盖度、语义候选不计分，却没有调用配置语言模型的问题。AI 开启时，目标岗位诊断和多岗位比较会真正调用当前模型；分析失败直接显示错误，不用规则结果冒充 AI 结果。

## 使用流程

1. 保存简历，在“诊断与优化”选择这份简历。
2. 尚未确定目标时，选择“分析适合的岗位方向”。结果引用简历原文，列出适合的职类及准备事项；点击“查找相关实时岗位”会按该方向查询国内招聘来源。
3. 选好 JD 后，选择“分析目标 JD 匹配度”。结果展示 AI 岗位适合度、判断理由、简历和 JD 引文、改进事项及模型与时间。
4. “推荐已保存岗位”仅从用户已保存的 JD 中推荐具体岗位。真实公司和来源链接由服务器提供，模型不能编造岗位 ID 或招聘链接。
5. 改写会显示前后差异、改善说明和事实来源。确认采纳后生成独立版本，保留原始简历。

诊断选项、证据、比较、历史和逐句来源均直接展示。简历目录不再使用删除线表示导出时隐藏的章节；章节自身仍保留显示/隐藏控制。

## 分析与数据

- AI 岗位适合度和规则材料覆盖度分开展示。旧历史记录仍是原规则结果，需要重新分析才能获得 AI 结果。
- AI 分析使用经历、技能、教育、语言、证书荣誉和自定义内容，不读取个人信息中的联系方式字段。证据引用必须逐字来自对应原文。
- 判断区分已有事实与未提供证据；缺少描述不能推断为不会。建议区分表达调整、先核实事实和先完成实践。
- 模型生成后还会核验引用和事实边界。数字、技能、角色及新增用途受到检查。校验失败会提供具体原因进行有限修订；仍失败则不保存分析或改写。
- 改写会检查是否只是复制或轻微替换，最多再尝试一次。没有明显改善时明确标记，避免把近乎相同的文本包装成优化。
- 匹配使用保存时的简历和岗位快照，校对保存为新的诊断记录。分析过程中原材料改变会拒绝保存，要求重新分析。
- 方向建议不创建招聘库，也不自动保存实时岗位。用户点击“使用并记住这份 JD”后，才加入已使用的 JD。

## 接口

| 接口 | 作用 |
| --- | --- |
| `POST /api/v1/career/directions` | 以 `resume_id`、`use_ai` 分析岗位方向及已保存岗位推荐 |
| `POST /api/v1/career/matches` | `use_ai` 控制 AI 匹配，`use_semantic` 单独控制辅助语义检索 |
| `POST /api/v1/career/matches/compare` | 对 2–5 份 JD 使用相同简历快照比较 |
| `POST /api/v1/career/rewrites` | 结合目标 JD、选中经历及补充事实改写 |
| `GET /api/v1/career/live/jobs?provider=ncss` | 国内多雇主岗位搜索，默认来源为国家大学生就业服务平台 |

国内招聘来源与 BOSS 等平台的核实结果见 [国内招聘来源接入记录](./国内招聘来源接入记录.md)。

## 验证记录

2026-09-08：后端全量回归 1152 项通过、2 项按配置排除；前端 64 个文件、542 项测试通过。随后补充的比较核对保留回归（10 项相关前端测试）及比较失败取消剩余请求、岗位方向版本一致性回归（25 项相关后端测试）通过。生产构建、TypeScript、相关 ESLint 和 Ruff 检查通过。浏览器实测岗位方向调用当前模型成功，推荐按钮正常启用，可将方向直接带入国内实时岗位搜索。

使用当前配置的 DeepSeek 和虚构材料实际调用：目标匹配 8.6 秒，岗位方向 7.3 秒，结构改写 4.0 秒；均返回模型信息和原文核验结果。已有清晰片段被正确标记为没有明显改善。国内岗位经前端代理及浏览器搜索取得 10 家企业的 10 份完整 JD。记录及改写前后示例见 [验证数据](./evidence/ai-diagnosis-2026-09-08.json)。这些结果是本次测试记录，耗时和岗位数量随模型及招聘来源响应变化。
