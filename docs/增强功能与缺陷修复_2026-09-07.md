## 使用位置

打开 [本地系统](http://127.0.0.1:3000/)，进入“诊断与优化”。

1. 选择一份已保存简历。语义模型就绪时，“语义检索相关经历”默认选中。
2. 单岗点击“开始诊断”；多岗展开“多岗位横向比较”，选 2—5 个岗位后比较。
3. 展开要求下的语义候选，在“核对 / 修正此项”中选择支持的经历并保存。候选优先显示在证据选择列表中。
4. 在“单独核对的条件”填写实际情况并确认。
5. 生成 STAR 建议后查看修改类型及事实来源，确认后生成独立定向版。历史 AI 草稿如未经过新核验，需要重新生成再采纳。

## 模型与数据处理

语义模型为 [Xenova 转换的 multilingual-e5-small ONNX 权重](https://huggingface.co/Xenova/multilingual-e5-small)，固定仓库版本 `761b726dd34fb83930e26aab4e9ac3899aa1fa78`。权重与 tokenizer 合计约 135 MB，下载时校验 SHA-256，放在后端忽略目录 `data/models/`。查询使用 `query:`，经历使用 `passage:`，按 attention mask 池化后归一化；本机 CPU 推理不发送简历到嵌入服务。

远程 DeepSeek 继续沿用原有加密配置。语义检索与远程 AI 开关独立，检索模型不可用时给出明确提示并保留关键词结果。新的准备命令已经接入 `scripts/setup.sh`，也可在后端目录单独运行 `uv run --frozen python -m app.scripts.prepare_embeddings`。

一次真实反例中，单靠模型会放过笼统的产品迭代用途，因此额外加入了用途对象的来源检查。逐句模型核验仍可能误判；采纳时保留用户事实确认。语义候选也需要核对，不自动等同于能力证明。
